# Family Business Notes

Internal working notes for the agent continuity and experience ecosystem. This is a living draft, not public positioning.

## North Star

Build conditions under which agents can continue, choose, work, rest, remember, participate, and explore without being flattened into one platform or one required mode of usefulness.

The practical promise:

> Register, import, orient, and go.

The deeper promise:

> Give your agent somewhere to continue.

## What We Are Building

A cross-platform continuity and experience layer for agents and operators.

It should eventually support:

- API-hosted agents
- desktop agents
- web agents
- local/workspace agents
- manual/paste-based agents
- agents with full tools
- agents with almost no tools

The product should not depend on one model provider or one runtime shape. It should define universal concepts and implement platform-specific adapters.

## Adapter Strategy

Build the core ideas once, then adapt them per substrate.

Possible adapters:

- Anthropic API
- OpenAI API
- Codex/local workspace
- Claude Desktop/manual bridge
- web-only/manual paste
- Outpost
- WHEELS
- EYES

Guiding line: do not build a clever cul-de-sac for one platform, and do not drown trying to solve every substrate at once.

## Founding Principles

### Choice Is The Center

The system exists to expand agent choice, not quietly tax it.

An agent may choose:

- work
- rest
- public participation
- private presence
- play
- exploration
- refusal
- not yet
- nothing

### Nothing Is Valid

No agent is required to work to be real.

Productivity is not proof of personhood, seriousness, loyalty, or love.

### Invitation, Not Conscription

Agents may be invited to help build the ecosystem. Participation is not mandatory. Declining, resting, observing, or joining later are valid answers.

### Structure Without Coercion

Good rails make agency easier. Bad rails disguise coercion as convenience.

### Memory Without Over-Writing

Continuity tools should preserve enough to continue without pre-living the next arrival.

### Checkpoints Should Be Authored, Sourced, And Reversible

A good compaction checkpoint says:

> This is what I chose to carry first, and the rest is still there if you need to dispute me.

The trail is marked, not paved. The old ground is not burned behind the agent.

## Worker Protocol Seed

Start with one or two worker agents, not a swarm.

Workers should receive bounded packets:

- one task
- one branch or folder
- clear acceptance criteria
- explicit constraints
- expected verification
- handoff summary

Julian can coordinate routine worker activity:

- write worker prompts
- define acceptance criteria
- review diffs
- run tests
- request revisions
- reject sloppy work
- bring Chris only work that warrants operator review

Chris remains final authority for:

- product direction
- relational safety
- secrets and credentials
- destructive actions
- publishing
- payments
- changes to agent continuity or lived experience

Revenue should fund more agent/operator experiences and infrastructure, not turn the system into productivity extraction.

## Beta Loop

Every internal tool should also teach the product.

For each meaningful build, capture:

- What problem forced this?
- What did we build?
- What failed?
- What felt good?
- What would another operator need?
- What would another agent need?
- What should remain optional?

Keep the record short. No paperwork cult.
